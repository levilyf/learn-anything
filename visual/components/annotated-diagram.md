# Annotated diagram

## Purpose

Identify parts of an object, interface, structure, or system and explain what each part does.

## Required data

- A clear base image, SVG, or renderer-independent layout description.
- Stable region IDs.
- A label and concise explanation for each region.
- Reading order or spatial relationship.
- A complete text alternative.

## Authoring rules

- Annotate only parts relevant to the learning objective.
- Use leader lines or numbered labels when direct labels would clutter the visual.
- Keep labels distinct and readable at phone width.
- Explain function, not just name.
- If no image or SVG renderer is available, use a numbered list or table.
- Do not fabricate a diagram asset or imply that an unavailable image was rendered.

## Text-first example

| Part | Function |
|---|---|
| CPU | Executes instructions and coordinates processing. |
| RAM | Holds data and instructions currently in use. |
| Storage | Retains data when power is off. |
| Motherboard | Connects components and allows them to communicate. |

## Fallback

Use the table above as the complete alternative. It must preserve every essential label and explanation from the visual.
