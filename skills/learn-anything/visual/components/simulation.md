# Interactive simulation

## Purpose

Let learners manipulate a simplified model and observe how changing inputs affects outcomes. A simulation is useful when experimentation reveals a mechanism more clearly than explanation alone.

## Required data

- Learning objective and model scope.
- Initial state.
- Explicit controls and allowed values.
- Deterministic or clearly described transition rules.
- Observable outputs.
- Reset behavior.
- Safety boundaries and known simplifications.
- A text-only exercise that teaches the same core idea.

## Authoring rules

- Label the model as a simplification, not a complete representation of reality.
- Explain which variables can change and which are fixed.
- Give the learner a prediction task before showing the result.
- Avoid collecting real credentials, personal data, or secrets.
- Do not connect to real targets or perform real-world actions unless separately authorized and safe.
- If interactive controls are unavailable, turn the same model into a worked scenario with learner-predicted outcomes.
- Never claim a simulation ran when the host only displayed its description.

## Cybersecurity safety

Use synthetic data, local toy models, or intentionally vulnerable labs with explicit authorization. Never use the simulation as a wrapper for unauthorized access, credential theft, stealth, malware, evasion, or exploitation of real systems.

## Text fallback

Present:
1. The starting configuration.
2. One variable for the learner to change.
3. A prediction question.
4. The expected model outcome.
5. An explanation of why the outcome follows from the model.
